The control system

Six kinds, five modifiers, three compositions. Two heights, two paddings, one radius, one curve, three durations. Every number below is resolved live from tokens.css and printed beside the control it applies to.

“Buttons and such need a consistent design. Tab buttons, regular buttons, markers — they all look different.” · “Spacing has to be premium, and the hover animation has to feel premium and consistent site-wide.”

View Hover anything to feel 160 ms in / 240 ms out.

1The shared base

Every control inherits all of this. A kind may vary exactly four properties — background, box-shadow, color, font-weight — and nothing else. Not height, not padding, not radius, not the transition, not the focus ring, not the press. Height is min-height, never vertical padding: that one rule collapses eight shipped paddings to two, and it is the direct cause of 7px 11px in Gradient Lab.

2The six kinds, in every state

1 · Primary — the one action a view exists for

Filled with --ctl-accent. One per view. Hover deepens the ground to --ctl-accent-press (5.59:1 → 7.86:1 white-on-blue). No border: the shipped .workCta carries a border the same colour as its own fill.

2 · Secondary — a boundary, not a fill

A --rim-1 inset hairline that becomes --rim-2 on hover while the ink goes --c700 → --c950. Two channels move and neither is a background. The rim is a box-shadow, so it is outside layout — which is why every Secondary can share one padding.

3 · Quiet — no ground, no rim, no radius anyone will see

The default and the largest population: 18 of the 40 classes, plus every nav item and menu row. There is nothing to declare — Quiet is the base. Hover is ink only. This is header.css:247 generalised to the whole site.

4 · Tab — a blue underline, never a blue fill

The underline is a ::before bar inset to --ctl-pad, not a border-bottom. Measured on apollo.html: the shipped .tvTab.on draws a 2px bottom border on a border-radius:14px box, so the "underline" is a swoosh that tapers out 14px before each end. 600 at rest so selection never reflows the row; selection is carried by ink (4.53:1 → 18.42:1) plus the rule.

5 · Chip / marker — usually not a target at all

The purest subtraction in the set. .baLabel today is 1px solid #E6E6E6 over background:#FDFDFD on a #FDFDFD page — an invisible box inside an invisible border — and its "after" state is a filled black pill. Ink and weight say it just as clearly.

6 · Field — the one kind that should look recessed

In scope because a select at 28.5px next to a button at 44px is the loudest inconsistency in Gradient Lab, and a form row cannot read as one object if its halves sit on different ladders.

3Modifiers — geometry only, never colour

Five, and they compose. A modifier may never touch the four properties a kind owns. Turn on “Show hit areas” to see the 36px rung’s ::after expansion.

The compact rung: three conditions, all of them

1 · Container — it sits inside a chrome object that is itself ≥44px. 2 · Hit area — it carries the ::after expansion to 44, applied by the modifier so it cannot be forgotten. 3 · Spacing — ≥8px between adjacent expanded targets. Any one failing means 44px. A pointer:coarse query is not the answer: coarse pointers need a bigger target, not a bigger ink box, and the ::after already gives 44×44 on every pointer type.

4Motion — three tiers, one curve

Measured across the whole site: 511 transition declarations, 30 distinct durations, 15 distinct easings. On controls specifically: 171 declarations, 10 durations, 4 easings. Only two motion tokens are consumed today.

The two curves that are used side by side and are not the same curve

ease-out is cubic-bezier(0,0,.58,1). The house curve is cubic-bezier(.2,.8,.2,1). At a quarter of the way through, the house curve has covered 77% of the distance and ease-out has covered 38%. In the mood menu today, .moodItem runs .1s ease-out and .moodGo — the row immediately below it — runs 160ms cubic-bezier(.2,.8,.2,1). Two adjacent rows of one menu, two curves, two durations.

What a premium hover is, as rules

The property set is closed. Five may animate on hover: color (all kinds), box-shadow (Secondary, Field), background-color (Primary only), text-decoration-color (.is-inline only), and transform — :active only, never :hover.

The asymmetry. In 160ms, out 240ms. Arriving is user-initiated and should feel instant; leaving is often incidental — crossing a row on the way somewhere else — and a slower release stops a row flickering as the cursor sweeps it. 1.5× is the smallest perceptible ratio that does not read as lag. Carve-outs — explicitly not UI motion

steps(2,end) ×24 and steps(2) ×2 stay verbatim. They are the case studies’ two-frame ink cut on the artefact swap (the same language as filter:url(#inkSm)) and the companion head’s eye. Character and craft, not chrome. All 126 animation: declarations across 51 durations — the goal sequence at 5600ms, the champion reveal, the 22 000ms ambient loop — belong to the game and the hero, and forcing them onto a 3-tier UI scale would be a category error. The 500ms content entrances (.ch, .csMeta, .reelCap) keep --enter-dur.

5Spacing — the between-control rhythm

One ladder, three rungs that matter, and the gap between groups is exactly 2× the gap between items, with no third value. That 2:1 is what lets a bar read as groups without a divider — the same argument as the type spec’s 3.8:1 heading ratio, turned sideways. 8px is a floor, not a preference: it is the separation two 44px targets need.

6Compositions — built from the kinds, not new kinds

The split control — a destination that also discloses

One element, not two. A link plus a caret button is two hit areas, two focus stops and two hover states, and it reads as glued rather than made. The caret is an 11px --ico-xs glyph inside the same anchor — one rung below the leading icon’s 18px, because a control with an 18px head and an 18px tail has no direction. Gap to the caret is 6px, not 8: the caret belongs to the label. Rotation is 160ms --ease-out, deliberately not a spring — an overshoot on an 11px glyph is a twitch, not weight. Open state takes the hover ink and no fill: open ≠ selected, and the menu is its own indicator.

Click to toggle. Hover-intent in --dur-intent 120 ms; close after --dur-state-out 240 ms.

The travelling active indicator

One shared element per row. transform only — never left/width, which re-solve layout on every frame of a 360ms move. Curve is --sp-settle, the one place a spring belongs on chrome: the indicator is an object with position and it should arrive rather than stop. It is never the only signal — the ink still goes --c500 → --c950 instantly, because mid-flight the bar marks neither tab.

Click a tab. Transform-only, 360 ms --sp-settle; jumps under reduced motion.

Menu rows and nav items are the same control

Same kind, same ink ramp, same 44px target, same focus ring, same 160/240ms hover — which is what “in the same style and design system” means, and it costs nothing because they were already the same control. Exactly three permitted differences: alignment (a menu is a vertical list; a bar is a horizontal row), width (100%), and icon size below 640px — the bar drops to 15px because it runs out of horizontal room, and a menu does not, because shrinking a menu’s icons makes it look like a different component from the bar that opened it. Desktop icon size is --ico-md 18px in both, which is already true today. Rows stack at gap:0.

The menu surface is the one place a shadow is permitted: --rim-2 + --sh-2. The no-shadow rule governs resting chrome; the tokens spec §4.2 sanctions --sh-2 for “a surface genuinely floating over content — an open menu, a tooltip.” Rows take --r-md 14px: --r-lg 20 minus the --sp-8 inset, per the concentric rule.

7The dark ground and the floating control

Five custom properties, no second component, no second layout — [data-surface="ink"] swaps the ink ramp, the rim and the focus ring. A Secondary that floats over arbitrary content adds background:--mat-3-solid, which is a material, not a fill: the one permitted addition in the system.
